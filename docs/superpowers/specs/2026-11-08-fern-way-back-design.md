# Fern way back, grace day, daily check-in and review — design

Date: 2026-11-08 · Status: draft for Kai's approval

## Why

A /roast review (2026-11-07) found Unfurl's target users — people who have
already quit two or three trackers — leave after a missed week because the
app shames them on return ("streak lost · was 12"). Kai agreed (2026-11-08) to:

- give a no-guilt way back after missed days;
- rewrite how misses appear while keeping the standing pillar *"nothing
  finishes silently; every miss shows its cost"* — show what was missed and
  what it cost, never the loss as punishment;
- have Fern ask once a day so nobody has to remember to log;
- have Fern give wins-first feedback that turns gaps into tiny habits/tasks.

The paywall that will sit right after the way-back moment is separate work.
This design leaves a single exit point (`onDone` of the way-back flow) where
it can be inserted later.

## Goals

1. A person returning after 2+ empty days is met by Fern with a catch-up, not
   a scorecard. One sentence or voice note fills in the gap as real records.
2. One missed day never breaks a streak (grace day).
3. No surface in the app says "lost". Misses read as facts with their cost.
4. A daily check-in at a time the person picks, answered through the existing
   capture path.
5. A Fern review — wins, then at most two gaps, how to improve each, and a
   one-tap "make it a habit / make it a task" — on the way back and weekly.

## Non-goals

- Paywall (separate work).
- Server-sent push for the check-in (local notification is enough; no new
  scheduler job).
- Notification quick-reply (text input inside the notification). No
  categories exist today; tapping opens the app.
- Changing how capture parses text (we only pass it a date range).

## Anti-goals (would be a failure even if it works)

- Any copy that reads as blame: "lost", "failed", "broke", red badges on the
  way back.
- Fern inventing records: a day the person did not describe stays empty
  (unknown), never logged as "missed" or zero by the AI.
- Weight-, body- or appearance-related feedback or suggestions.
- More than two suggestions at once, or suggestions bigger than a first step.
- A toast for anything except habit/task ticks.
- Truncated task/habit titles.

## Constraints

- Habit streak logic exists twice, `shared/prototype/habits/logic.ts:232` and
  `backend/app/modules/habits/logic.py:266`, pinned by the golden fixture
  `backend/tests/golden/habits-logic.json` (generated by
  `scripts/golden/habits.golden.test.ts`). The grace rule changes both and
  regenerates the fixture.
- The on-target day streak exists in `shared/prototype/dash/hooks.ts:270`
  (`useOnTarget`) and `backend/app/modules/stats/logic.py:135-222`.
- Schema changes via Alembic; regenerate the frontend and mobile clients.
- Fern cost is $0.020–0.027 per turn. Budget: catch-up = 1 capture turn,
  review = 1 call, check-in = 1 capture turn. Nothing runs on a schedule.
- Backend tests only against the 55440 throwaway DB.

## Design

### 1. Grace day

**Rule (my call, recommended):** inside a run, a single missed scheduled day
is bridged — counted as neutral, not as a break — provided the next
scheduled day is done/partial (or is today and still pending). Two missed
scheduled days in a row break the run. At most one grace per rolling 7
calendar days per streak; a second lone miss inside that window breaks it.

- Applies to habit streaks (`computeStreaks` / `streaks()`) and the on-target
  day streak (`useOnTarget` / `on_target_stats`).
- `streaks()` gains `graceDays: string[]` (the bridged days inside the
  current run) so the UI can say "grace day used".
- The bridged day does not add to the count (a 12-day run with one grace day
  reads 12, not 13).
- *Builder calls:* "missed" means a scheduled day per the habit's existing
  `cellFor` cells (unscheduled days are already neutral), so a
  3-days-a-week habit gets grace on its scheduled days. Graces inside one run
  must be at least 7 calendar days apart, checked while walking the run.
  A grace held for today-pending is provisional: if today also ends missed,
  tomorrow's walk sees two missed scheduled days in a row and the run ends —
  no retroactive state. `graceDays` is added to every API schema that
  exposes streaks, and clients are regenerated.
- Python and TS change together; golden fixture regenerated with new cases
  (lone miss bridged, two misses break, two lone misses inside 7 days break,
  grace on the last scheduled day before today-pending).

### 2. How misses appear (replacing "streak lost · was N")

`StreakChip` (`mobile/src/prototype/motion.tsx:572`) gets a `miss` prop in
place of `lost`:

| State | Chip text | a11y label | Colour |
|---|---|---|---|
| Run alive, grace used | `🔥 12 · grace day used` | "12-day streak, grace day used" | flame (warn) as today |
| Run ended yesterday | `2 days missed · run of 12 ended` | "2 days missed, 12-day run ended" | neutral muted, no red |
| Gap longer than grace — only if Kai picks "paused" in Q1 | `3 days missed · streak paused at 12` | same | neutral muted |

The cost (the run that ended) stays visible, satisfying the pillar; the
punishment framing (red, "lost") goes. `streakLost()` in `rewards.ts:31`
becomes `streakMiss()` returning `{missed, run, grace}`.

Copy sweep, same tone:
- `daily-strips.tsx:35` "Yesterday: off target · N-day streak ended" →
  "Yesterday: off target · run of N ended" (or "· grace day used" when bridged).
- `habit-share.tsx:160,344`, `habits-home.tsx:492` "Broken streaks" →
  "Runs that ended", `habit-detail.tsx:490`.
- Yesterday page (`screens/yesterday.tsx`): misses list headed "What slipped",
  each row keeps its cost line; no "lost".
- `local-reminders.ts:506` "🔥 Your N-day streak is at risk" stays (it is a
  forward nudge, not blame) but adds "— a grace day covers one miss" when
  the grace is still available.
- Test `__tests__/daily-loop.test.tsx:339` updated to the new text.

### 3. Way back after missed days

**Trigger (on device, local-first):** `lastActiveDay()` = the latest business
day with any record: habit log (any status), task completion, finance
record, workout, run, meal, journal entry or capture. If
`today − lastActiveDay ≥ 3` (i.e. 2+ fully empty days in between), the
person has at least one active day before (a fresh install idle for two
days never triggers it), and the way back has not been
shown for this `lastActiveDay`, Today opens the way-back screen once
(route `/today/welcome-back`). Dismissing it records the `lastActiveDay` so
it never re-appears for the same gap.

**Screen, top to bottom:**
1. Fern sprite (calm mood), "Welcome back." and one quiet line:
   "You were away {N} days. Tell me roughly how they went and I'll fill
   them in — or skip and start from today."
2. One input with mic (live dictation already exists), placeholder
   "e.g. last week was chaos — skipped gym, ate takeaway most nights".
3. Primary "Catch me up" (send icon); secondary "Start from today"
   (no guilt, no record written).
4. After sending: the normal capture cards for what Fern parsed (person
   confirms/undoes as usual), then **"Here's where you are"** — three
   deterministic lines, no AI:
   - streaks: "Gym: 3 days missed · streak paused at 12" / "Reading: 🔥 9 ·
     grace day used" (the top two habits by run length);
   - today: "Today: 3 habits and 2 tasks" (titles wrap);
   - a win: the most recent on-target day or milestone before the gap.
5. Then the Fern review (§5) for the gap range, then "Back to today"
   (`onDone` — the future paywall insertion point).

**Catch-up parsing (backend, reuses capture):** the mobile sends a normal
capture (`POST /capture/stream`) with `hint: "catch_up"` and two new optional
fields on `CaptureIn`: `range_from`, `range_to` (business days). The capture
agent already supports `days_ago` on expense, income, habit log, workout and
meal args (`capture/agent.py:493`). With the hint, the agent's prompt gets
the range and the rule: *log only what the person stated; if they named a
day, use it; if they described a span without a day ("ate takeaway most
nights"), make one record on the last day of the range with the span in its
note; never invent per-day entries; "skipped X" writes nothing* (the habit's
days simply stay missed). `days_ago` is clamped into the range server-side.
*Builder calls:* `hint` is whitelisted in `capture/engine.py:188`; add
`"catch_up"` and `"checkin"` to the Literal. Dated statements become typed
records (habit log, workout, meal, expense…) on that day; a stated day
outside the range is clamped to the nearest range end. Undated span
statements ("ate takeaway most nights", "went gym a couple of times") become
**one journal entry** on the last day of the range — never a typed record on
an invented day. "Here's where you are" is computed after the person has
confirmed/undone the cards, so a catch-up like "did gym Tuesday" repairs the
streak naturally through the normal grace rule.
One capture turn total. The rules fallback (no model) logs the text as one
journal entry on the last day of the range.

### 4. Daily check-in

- **Setting:** Me → Notifications gains "Daily check-in" (switch + time,
  using `time-input.tsx`). Default off; time defaults to the existing
  `dashStore.push.evening` (21:00). Also offered once at the end of the first
  way back: "Want Fern to ask each evening?" (switch inline, no modal).
  Stored in `dashStore.push.checkin` (`"21:00"` or `""`) and synced to a new
  `profile.push_checkin` column (Alembic).
- **Notification:** a `daily {hour, minute}` local reminder in
  `planReminders` (`local-reminders.ts:189`), title "How did today go?",
  body "Tell Fern in a sentence — it logs it for you.", href
  `/capture?checkin=1`. Respects quiet hours. Sending a check-in writes
  `dashStore.push.lastCheckin = today`; the planner (which rebuilds on store
  change) skips today's instance when it is set, so the first fire is
  tomorrow.
- **Answer:** the link opens the capture drawer with Fern's question as the
  first bubble (static, no model call) and the mic ready. The reply goes
  through `sendCapture` with `hint: "checkin"` → the existing parse path.
  One capture turn.

### 5. Fern review with suggestions

**Endpoint:** `POST /companion/review` `{kind: "way_back" | "weekly",
from_day, to_day, dismissed: string[]}` → `{wins: Point[], gaps: Gap[],
source: "ai" | "rules"}`. Modelled on `dashboard/miss_analysis.py`:

- Facts come from existing stats (`stats_public` day series, habit streaks,
  misses, task completions, workouts, focus) for the range plus the 7 days
  before it, each fact with an id. Weigh-ins, body measurements and calorie
  targets are **excluded from the input entirely** (care boundary).
- One model call (`ai.resolve_model(ctx, "chat")`, metered with
  `record_usage`), JSON output:
  `wins` (1–3, each `{text, fact_ids}`), `gaps` (0–2, each `{text, how,
  suggestion: {kind: "habit"|"task", title, days_per_week?}, fact_ids}`).
- Server validation: drop any item whose `fact_ids` are not in the input;
  drop suggestions matching a body/weight/diet term list; drop suggestions
  whose title matches a `dismissed` title or an existing habit/task; cap 2
  gaps; titles ≤ 60 chars. Prompt rules: suggestions are a first step
  ("10-minute walk after lunch, 3 days a week"), never a goal; a missing
  fact is unknown, not zero.
- Nothing slipped → wins only, no gaps (still one call for wins; or rules
  when nothing to say).
- Cached per `(user, kind, from_day, to_day)` with a fingerprint of the
  facts in a new `fern_review` table (Alembic), like `MissAnalysis`.
- AI off / cap / no model → rules review: wins from on-target days and
  streaks; gaps from the two most-missed habits with a templated tiny
  suggestion ("{habit}, {n} days a week" where n = done days + 1, min 2).
- Provider failure → 503, card shows Retry.

**Where it shows (mobile):** a `FernReviewCard` block:
- way back: under "Here's where you are", requested automatically (the
  person just asked to catch up);
- weekly: on the weekly review screen (`screens/dash-reviews.tsx`) behind an
  "Ask Fern for a review" button (AI on demand only).

Card layout: Wins first (green check icon per line), then each gap: what,
how, and one button "Make it a habit" or "Make it a task" (icon + label,
by `suggestion.kind`) plus an × dismiss. Tapping creates it locally
(`createHabit` with `days_per_week` schedule / `createTask`), and the row
turns into "Added to habits ✓" with a link to it — inline confirmation, no
toast. Dismissed titles are kept on device for 30 days and sent as
`dismissed` (per device, not synced — my call; a second device may
re-suggest once). The weekly button runs the same AI switch / spend-cap
gate as the Yesterday analysis; when it falls back to rules the card shows
the same layout with no AI label change.

## Open question for Kai

**Q1. What happens to a streak when the gap is longer than the grace day.**
Kai's example reads "3 days missed · grace day used · streak paused at 12".

- **A — run ends (recommended).** Honest and stateless: the chip reads
  "3 days missed · run of 12 ended", best run kept, and the way back says
  "your best run of 12 is still yours". Catching up with real activity
  ("did gym Tuesday") still repairs it through the grace rule. Only a copy
  change plus the grace rule.
- **B — paused, resumes at 12.** On a way back the run is frozen and picks up
  at 12 when the person logs again, once per 30 days. Streaks are computed
  from logs today, so this needs a stored pause marker per habit (new table,
  Alembic, both TS and Python streak logic, the golden fixture, and sync).
  Roughly a third more build, and a streak that survives a week away means
  less.
